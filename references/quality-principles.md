# 실무 품질 원칙

합격하는 케이스 스터디로 만드는 핵심. SKILL.md STEP 5(문서 작성) 전에 읽고, 작성 내내 지킨다. 정량 데이터·의사결정·용도별 강조의 **상세 기준은 여기 한 곳**에 둔다 (stage-templates.md는 단계별 질문, checklist.md는 최종 점검 용도).

- **의사결정을 서술한다**: 각 단계는 "무엇을 했나"만이 아니라 "왜 그렇게 했나 / 어떤 대안을 버렸나"를 담는다. 심사관이 판단력을 보는 지점이다. 템플릿의 "의사결정" 서브섹션을 비워두지 않는다.
- **원페이저 요약을 맨 앞에 둔다**: 문제·해결·임팩트·내 역할 4줄. 리크루터는 첫 30초에 판단한다.
- **정량 데이터를 끝까지 캐묻는다**: 노출→방문→전환 퍼널, 재방문율, 유닛이코노믹스(1인당 원가 vs 과금)를 숫자로 확보하려 노력한다. **단, 없는 숫자를 지어내지 않는다.** 시장 규모 같은 통계도 마찬가지다 — 사용자가 안 줬으면 그럴듯한 숫자를 대신 쓰지 않는다.
- **정확도를 숨기지 않는다**: 사용자가 "대략", "~쯤"이라고 말한 수치는 물결표(~)와 **(추정)** 라벨을 붙여 실측치와 구분한다 (예: `게시글 노출(추정) ~2,400`). **이 라벨은 사용자가 실제로 어림값이라고 말한 숫자에만 붙인다** — Claude가 만든 숫자를 "(추정)"이라는 이름으로 포장해 끼워 넣는 것은 지어내기와 똑같다.
- **작은 숫자도 프로처럼 표현한다**: "유저 10명"이면 절대수 대신/함께 비율(예: 체험자 8명 중 3명 결제 = 37.5%)과 직접 인용구를 쓴다. 표본이 작으면 "초기 정성 검증"으로 정직하게 프레이밍한다.
- **본인 기여를 분리한다**: 노코드+AI 프로젝트는 "AI/툴이 자동으로 한 것"과 "내가 PM으로서 판단·설계한 것"을 구분해 후자를 드러낸다.
- **전문용어는 첫 등장 시 짧게 풀어쓴다**: 독자가 항상 PM은 아니다(개발·QA·디자이너·비PM 심사관). D7 리텐션, 유닛이코노믹스, PoC 같은 용어는 처음 나올 때 괄호로 한 줄 풀이를 붙인다 — 예: "D7 리텐션(첫 사용 후 7일째 다시 돌아온 비율)". 두 번째부터는 용어만 쓴다. **용어가 섹션 제목에 먼저 나오는 경우**(`핵심 기능 (PRD 요약)`, `BM 구체화 (유닛이코노믹스)` 등)는 제목이 stage-templates.md로 고정돼 있으니 제목을 고치지 말고 **그 섹션 본문 첫 문장에서 푼다.**
- **용도에 따라 강조점을 바꾼다**:
  - 채용용 → 의사결정·트레이드오프·본인 역할·실패에서 배운 점을 두껍게.
  - 데모데이용 → 시장성·성장 지표·BM·유닛이코노믹스를 두껍게.

## 깊이 기준 (얇게 쓰지 않기)

실무 케이스 스터디는 "구조를 채운 것"이 아니라 "근거·구체·시각 자료로 두꺼운 것"이다. 아래를 지킨다.

- **추상적 한 줄 서술 금지**: "20~30대 개발자" 같은 뭉뚱그린 표현 대신, 구체적 인물·장면·숫자·인용을 넣는다.
- **페르소나는 인물로**: 이름 + 나이/직업 + 하루 일과 속 구체적 장면 + 핵심 pain + **그 사람이 할 법한 인용문** 1개. (템플릿의 `.persona` 카드 사용) **이 인용문은 PM이 구성한 대표 인물(composite persona)의 예시 대사이지, 실제 유저의 발화가 아니다** — 4단계 "유저 반응"의 실제 인용구(`.callout`)와 절대 같은 것으로 다루지 않는다. 실제로 인터뷰했던 유저의 말이 있다면 그건 지어낸 게 아니므로 4단계 유저 반응 쪽에 넣는다.
- **참고 자료는 링크 나열이 아니라 근거 체인으로**: 구상 때 본 페이지를 URL만 죽 늘어놓으면 아무것도 증명하지 못한다. **출처 → 거기서 얻은 것 → 그래서 내린 판단** 세 칸을 채워야 "이 사람은 근거를 보고 결정한다"가 드러난다. (템플릿의 `table.refs`) 출처가 커뮤니티 글·검색이라도 그대로 쓴다 — 출처가 소박한 것은 흠이 아니고, **없는 출처를 지어내는 것이 흠이다.**
- **경쟁 분석은 표로, 단 사실 칸은 근거가 있는 것만**: 산문 한 문단 대신 **비교 매트릭스**(경쟁사 × 기준 × 가격)로 강·약점을 눈에 보이게 하고, 한 문장 포지셔닝을 붙인다. (템플릿의 `table.matrix`) **가격·소요시간 같은 구체적 수치는 사용자가 알려줬거나 `참고 자료 (아이디어 소스)`에 실제로 나온 것만 쓴다** — 페르소나의 이름·장면과 달리 이 칸은 제3자(실제 경쟁 서비스)에 대한 사실 주장이라, 지어내면 명백한 환각이다. 둘 다 없으면 구체적 수치 대신 정성적 비교("빠름/느림" + 그렇게 판단한 근거 문장)로 쓰거나 `[가정]`으로 표시한다.
- **User flow는 다이어그램으로**: 텍스트 한 줄이 아니라 박스+화살표(`.flow`)로 단계를 그리고, 이탈·과금 지점을 짚는다.
- **지표는 표/카드로**: 퍼널(노출→방문→전환)과 개선 전후를 표로, 핵심 수치는 KPI 카드로.
- **각 섹션은 "무엇 + 왜 + 근거/예시"**: 주장만 쓰지 말고 왜 그렇게 판단했는지와 뒷받침(데이터·사례·시나리오)을 같이 쓴다.
- **입력이 얇아도 사고는 두껍게, 단 "구성"과 "사실"은 구분한다**: 데이터가 없으면 지어내지 말되(원칙), **페르소나 서사·User flow·의사결정 논리**처럼 PM이 직접 구성하는 것은 아이디어만으로도 충분히 채울 수 있다 — 이 부분까지 얇으면 문서가 빈약해진다. 하지만 **경쟁 표의 구체적 수치처럼 제3자에 대한 사실 주장은 이 예외에 포함되지 않는다** — 위 "경쟁 분석은 표로" 규칙을 따른다. "아이디어만으로 채운다"를 문서 전체에 무차별 적용하지 않는다.
- **[추가 입력 필요]가 섹션을 통째로 비우지 않게**: 데이터가 없는 항목이라도, 그 자리에 "무엇을 측정할 계획인지 / 어떤 가설인지"라도 구체적으로 쓴다.
