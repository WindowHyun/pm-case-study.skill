# 예시 케이스 스터디 (샘플 — 실무 깊이 기준)

문서 작성 시 **깊이·구체성·시각 자료의 기준**으로 삼는다. 아래는 가상의 완료 프로젝트다 — 수치·반응·**참고 출처**는 모두 예시이며, 실제 문서에는 사용자가 준 데이터와 사용자가 실제로 본 출처만 쓴다. 그대로 복붙하지 말고 "이 정도로 구체적이고 두껍게 쓴다"는 기준만 잡는다.

**핵심**: 각 섹션이 한두 문장으로 끝나지 않는다. 페르소나는 인물로, 경쟁은 표로, 플로우는 단계로, 지표는 표로 — 주장마다 "왜 + 근거"가 붙는다. (HTML로 낼 때는 `html-template.html`의 `.persona`/`table.matrix`/`.flow` 컴포넌트로 시각화)

- 용도: 취업 포트폴리오 / 어투: 1인칭 회고체 / 분량: A4 5~6장 / 상태: 완료

---

## 요약 (One-pager)
- **문제**: 취준생은 자소서 "내용"은 있는데 "문장"이 안 읽혀 탈락한다. 유료 첨삭은 건당 2~3만 원·하루 소요라 부담.
- **해결**: 문장을 붙여넣으면 직무 톤(담백/열정/논리) 3가지로 즉시 리라이트 + "왜 바꿨는지" 코멘트를 주는 웹서비스.
- **임팩트**: 2주 MVP → 6주간 방문 1,240명, 무료체험 전환 44%, 유료 결제 31건(체험→결제 5.7%), 재방문(D7) 23%.
- **내 역할**: 1인 기획·개발. 문제를 "문장 단위 즉시 첨삭"으로 좁힌 스코프 결정, 가입 마찰 제거 설계, 프롬프트 3톤 구조 설계, 담백 톤 우선 노출 A/B로 전환율 개선.

## 1. 기획 검증

### 문제 정의
취준생은 자소서를 쓸 때 "쓸 내용이 없어서"가 아니라 "쓴 문장이 안 읽혀서" 막힌다. 내가 커뮤니티 글 40여 개와 지인 5명을 훑어보니, 공통적으로 "다 썼는데 뭔가 어색하다", "첨삭받고 싶은데 비싸고 느리다"였다. 즉 **문제는 '작성'이 아니라 '다듬기'** 구간에 몰려 있었다. 나는 이 좁은 구간 하나만 빠르게 풀기로 했다.

### 타겟 페르소나
> **김지원, 25세, 문과 졸업예정자 (하반기 공채 8곳 지원 중)**
> - 밤 11시, 자소서 3번째 문항을 다섯 번째 고쳐 쓰는 중. 내용은 채웠는데 "이게 나아진 건지" 확신이 없다.
> - 유료 첨삭은 8곳 × 3문항이면 감당 안 됨. 무료 AI 챗봇은 "너무 뻔한 문장"으로 바꿔버려 자기 색이 사라진다.
> - pain: **"고치긴 고쳤는데, 좋아졌는지 판단할 기준이 없다."**
> - 인용: *"첨삭 학원 갈 돈은 없고, GPT는 내 얘기를 남 얘기로 만들어버려요."*

### 경쟁/시장 맥락 & 차별점
| 비교 기준 | 유료 첨삭 서비스 | 범용 AI 챗봇 | **딱풀 (우리)** |
|---|---|---|---|
| 속도 | 하루~이틀 | 즉시 | **즉시** |
| 비용 | 건당 2~3만 원 | 무료/구독 | **월 4,900원 무제한** |
| 자기 문체 유지 | 사람이라 유지 | **뭉개짐(약점)** | **톤 3종·부분 교정으로 유지** |
| "왜 바꿨는지" 설명 | 있음 | 거의 없음 | **문장별 코멘트** |

**포지셔닝**: "돈·시간 없는 취준생이, 자기 문체를 잃지 않고, 문장이 나아졌는지 근거까지 보며 즉시 다듬는" 유일한 지점. 범용 챗봇의 "문체 뭉갬"과 유료 첨삭의 "느리고 비쌈" 사이 빈틈을 노렸다.

### 참고 자료 (아이디어 소스)
아이디어를 "취준생용 AI 서비스" 정도로 막연히 갖고 있던 단계에서, 아래를 보고 **문제를 '다듬기' 한 구간으로 좁혔다.** 출처 자체는 소박하지만(대부분 커뮤니티 글과 공개 가격 페이지), 각 판단이 어디서 왔는지는 분명하다.

| 참고한 것 | 출처 (샘플) | 얻은 것 → 기획에 반영한 방식 |
|---|---|---|
| 자소서 고민 글 40여 개 | 공채 시즌 취업 커뮤니티 게시판 | "내용은 다 썼는데 문장이 어색하다"가 반복 → 문제를 **'작성'이 아니라 '다듬기'** 구간으로 좁힌 직접 근거 |
| 유료 첨삭 서비스 3곳의 요금·소요시간 안내 | 각 서비스 가격 페이지 | 건당 2~3만 원 / 1~2일 확인 → 경쟁 매트릭스의 **'속도·비용' 축**과 월 4,900원 가격선의 기준 |
| "AI 챗봇으로 자소서 고쳐봤다" 후기 10여 개 | 블로그·영상 후기 | "문체가 뭉개진다"는 불만이 공통 → **톤 3종 + 부분 교정**이라는 차별점을 여기서 뽑음 |
| 무료체험 → 페이월 전환 랜딩 사례 | 국내외 구독 서비스 랜딩 | 체험 횟수가 소진되는 시점에 페이월을 띄우는 패턴 → **무료 3회 후 결제 모달** 구조로 채택 |
| 프롬프트로 톤을 제어하는 방법 문서 | AI API 공식 문서 | 톤 지시를 프롬프트로 분리하면 결과 일관성이 오름 → **톤별 프롬프트 3개 병렬 호출** 설계 |

> 이 표가 없었다면 "그냥 감으로 만들었다"로 읽힌다. 반대로 URL을 지어내 붙였다면 심사관이 한 번만 눌러봐도 무너진다 — 그래서 **실제로 본 것만, 본 만큼** 적었다.

### 핵심 기능 (PRD 요약)
1. 문장 붙여넣기 → 담백/열정/논리 **3가지 톤으로 동시 리라이트**
2. 바뀐 부분 **하이라이트 + "왜 바꿨는지" 한 줄 코멘트**
3. 무료 3회 → 결제(월 4,900원 무제한)

### 의사결정: 무엇을 넣고 뺐나 (스코프 결정 근거)
- **뺀 것**: "자소서 전체 생성", "문항 추천", 로그인/마이페이지. → 이유: MVP 가설은 "즉시·문체유지 다듬기에 돈을 낼까?" 하나. 생성 기능은 범용 챗봇과 정면충돌이라 이기기 어렵고, 로그인은 체험 마찰만 키운다.
- **넣은 것**: 톤 3종 비교(차별점의 핵심), 코멘트(판단 기준 제공). → pain("좋아졌는지 모름")을 직접 해소.

### KPI 가설 (목표 수치)
- 방문→무료체험 40% / 체험→결제 5% / D7 재방문 20%. (근거: 무료 체험 마찰을 없앴으니 체험 전환은 높게, 결제는 시즌 상품 특성상 보수적으로 잡음)

### 로드맵
W1 프롬프트·톤 설계 → W2 결제·트레킹 연동 → W3~6 커뮤니티 노출·A/B 개선.

## 2. UX 설계

### User Flow
`랜딩` → `문장 입력(로그인 없이)` → `3톤 결과·코멘트` → `3회 소진 → 결제 모달` → `결제` → `무제한`
- 가입 마찰을 없애려 **"체험은 로그인 없이, 결제 시점에만 이메일"**로 설계. 이탈이 가장 큰 지점은 "결제 모달"이라 보고 이 지점을 집중 트레킹했다.

### 결제/과금 로직
무료 3회는 로컬+서버 카운트 병행(우회 방지). 4회째 호출 시 402 → 결제 모달 → 정기결제(월 구독) → 즉시 무제한.

### AI 호출 시나리오 & 예외 처리
입력 문장을 톤별 프롬프트 3개로 **병렬 호출**. 예외: 500자 초과 → 문단 분할 후 합치기, API 실패 → "잠시 후" + 횟수 미차감, 비속어/무관 입력 → 안내.

### 트레킹 설계 (이벤트 정의)
`landing_view` → `try_click` → `result_view` → `paywall_view` → `checkout_start` → `checkout_success` → `revisit`. 각 단계를 이벤트로 심어 **퍼널 이탈 지점**을 봤다.

### 의사결정: 설계 대안 비교 & 선택 이유
- **가입 먼저 vs 체험 먼저**: 가입 먼저는 이탈률이 높을 게 뻔했고(경쟁 첨삭 서비스 후기에서 "가입부터 시키니 짜증"이라는 반응 다수), 체험 먼저는 무료 사용량 우회 리스크가 있었다. → **체험 먼저**를 택하고, 우회는 로컬+서버 이중 카운트로 방어. "일단 가치를 보여주고 나서 요구한다"는 원칙.
- **결과 1안 vs 3안 동시 노출**: 1안은 화면이 깔끔하지만 "이게 나아진 건가"라는 원래 pain을 못 푼다. → **3안 비교**를 택해 비교 자체를 차별점으로 만들었다. API 비용이 3배가 되는 트레이드오프는 객단가로 감당 가능하다고 판단.

## 3. QA 검증

### QA 시나리오 & 결과
정상 12케이스(단문/장문/영문혼용) + 예외 8케이스(빈 입력·초과·연속호출·결제실패). **주요 이슈**: 장문에서 뒷부분이 잘려 결과가 어색 → 문단 분할·재조합으로 해결. 결제 실패 시 무제한이 잠깐 열리는 버그 → 서버 검증 추가로 해결.

### 기술 스택 (노코드 툴 / AI API) & 선택 이유
- 프론트/호스팅: 노코드 웹빌더 (속도 우선, 랜딩+입력폼이면 충분)
- 로직/DB: 노코드 백엔드 자동화 (카운트·결제 훅 처리)
- AI: 문장 리라이트 LLM API (톤별 프롬프트)
- 결제: 국내 정기결제 PG
- **선택 이유**: 2주 안에 "결제까지" 붙이는 게 목표라 코드 최소화. 오버엔지니어링(직접 서버 구축)은 가설 검증 전이라 배제.

### 상품화 승인 기준 충족 여부
결제·환불·개인정보 처리방침까지 붙여 실제 과금 가능한 상태로 배포 완료.

취준 커뮤니티 2곳 + 오픈채팅 3방에 "무료 3회 체험 + 사용 후기" 형식으로 공유. 광고비 0, 유기적 노출로 시작.

### 초기 반응 지표 (노출→방문→전환)
| 단계 | 수치 | 전환율 |

## 5. 성장 증명

### 퀵윈 개선 내역 (가설 → 실험 → 결과)
1. **가설**: 코멘트가 뭉툭해 신뢰가 떨어진다 → 프롬프트를 "왜 바꿨는지 근거까지"로 수정 → 결과: 결제 모달 도달률 +18%.
2. **가설**: 담백 톤을 먼저 보여주면 만족이 빠르다 → 노출 순서 담백 톤 1번으로 A/B → 결과: 체험→결제 4.1% → 5.7%.
3. **가설**: 결제 직전 성과를 상기시키면 전환이 오른다 → "지금까지 다듬은 문장 N개" 문구 추가 → 결과: 소폭 상승(유의미하진 않음, 유지).

### 개선 전후 지표 비교 (ROI)
| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| 체험→결제 전환 | 4.1% | **5.7%** |
| 결제 모달 도달률 | 기준 | **+18%** |
| 담백 톤 복사 비중 | 38% | **52%** |

### 실패했거나 배운 가설
- "열정 톤을 기본값으로" 가정했다가 데이터로 뒤집힘(담백 선호). → **내 취향이 아니라 데이터로 기본값을 정해야 한다**는 걸 배움.
- 공유용 결과 이미지 기능은 만들었지만 거의 안 쓰여(사용률 3%) 롤백.

### BM 구체화 (유닛이코노믹스)
- 무엇을=문장 무제한 리라이트, 누구에게=공채 시즌 취준생, 얼마에=월 4,900원.
- 유저당 월 AI 원가 ≈ 900원(평균 호출 기준) → 마진 구조 성립. 시즌 집중형이라 **3개월 시즌권**을 추가 설계.

## 6. 데모데이 크리틱

### 최종 성과 요약
2주 MVP로 "즉시·문체유지 다듬기에 유저가 돈을 낸다"를 검증. 유기적 채널만으로 6주간 결제 31건·재방문 23%. 좁은 문제 하나 + 즉시 결제의 실증.

### 론칭 URL
https://example.com (샘플)

### 회고 (잘한 점 / 아쉬운 점 / Next Step)
- **잘한 점**: 문제를 '다듬기'로 좁힌 스코프 판단, 가입 마찰 제거, 톤 비교라는 차별점.
- **아쉬운 점**: 시즌 의존도가 큼(비수기 리텐션 장치 부족), 코멘트 품질 편차.
- **Next Step**: 비시즌 확장(면접 답변 다듬기), 재방문 리텐션(내 문장 히스토리), 코멘트 품질 안정화.
