# 최종 산출물 체크리스트

SKILL.md 6단계(완성도 체크)에서 사용한다. 문서 작성 완료 후 아래 항목이 문서 어딘가에 반영됐는지 확인한다. 빠진 항목은 사용자에게 알린다.

**방법론 산출물 (9종)**
- [ ] 유저 리서치 기반 페르소나 정의 — (1. 기획 검증)
- [ ] 마일스톤 로드맵 — (1. 기획 검증)
- [ ] 표준 PRD — (1. 기획 검증)
- [ ] 트레킹 설계를 반영한 유저 행동 경로 — (2. UX 설계)
- [ ] 핵심 지표(KPI) 분석 — 실제 대시보드가 없으면 **지표 표/스크린샷**으로 대체 가능 — (2. UX 설계 ~ 5. 성장 증명)
- [ ] 노코드 + AI API로 실제 동작하는 MVP — (3. QA 검증)
- [ ] BM 반영 수익 모델 & 론칭 프로덕트 — (5. 성장 증명 ~ 6. 데모데이 크리틱)
- [ ] 유저 데이터 기반 개선 방향 — (5. 성장 증명)
- [ ] 상용화 도메인 URL 론칭 — 미완료 시 **계획 URL/도메인 후보**로 대체 — (6. 데모데이 크리틱)

**실무 설득력 요소 (채용·데모데이에서 실제로 평가되는 부분)**
- [ ] 원페이저 요약 (문제·해결·임팩트·내 역할) — 맨 앞
- [ ] 경쟁/시장 맥락 & 차별점 — (1. 기획 검증)
- [ ] **참고 자료 (아이디어 소스) — 필수**: 구상 때 본 페이지·출처 + "얻은 것 → 기획에 반영한 방식" — (1. 기획 검증)
- [ ] 의사결정 서술 (대안 비교 → 선택 근거) — 각 단계
- [ ] 본인 기여 구분 (AI/툴이 한 것 vs 내가 판단한 것)
- [ ] 정량 지표 or (작으면) 비율+인용구 — (4~5단계)

프로젝트가 아직 완료되지 않았다면 해당 항목은 체크하지 않아도 되지만, 문서에는 반드시 "계획" 형태로라도 언급되어야 한다.

**단, `참고 자료 (아이디어 소스)`는 이 예외의 대상이 아니다.** 구상 단계 프로젝트라도 "무엇을 보고 이 아이디어에 도달했는지"는 존재하므로 반드시 채워야 한다. 비어 있으면 최종 파일(HTML/PDF)을 만들지 말고 사용자에게 출처를 다시 요청한다 — 출처를 지어내서 채우는 것은 금지.
