# 단계별 질문 목록 & 문서 템플릿

SKILL.md 워크플로우의 STEP 2(갭 분석), STEP 3(질문 작성), STEP 5(문서 작성)에서 참고한다. (**STEP N**은 작업 순서, **N단계**는 아래 프레임워크 단계다.)

> **이 파일이 6단계 섹션 구조의 단일 원본이다.** 구조를 바꾸면 SKILL.md 요약표, html-template.html, example-case-study.md, checklist.md를 함께 갱신할 것 (SKILL.md "유지보수 규칙" 참고).

문서는 **원페이저 요약(본문 앞 블록) → 6단계 본문** 순서로 쓴다. 요약은 단계가 아니라 맨 앞에 얹는 요약 블록이다. 그리고 각 단계에는 결과 나열뿐 아니라 **의사결정(왜 그렇게 했나 / 어떤 대안을 버렸나)**을 함께 서술한다 — 실무 심사관이 가장 보고 싶어 하는 부분이다.

**얇게 쓰지 않는다**: 페르소나는 인물(이름·장면·인용)로, 경쟁은 비교표로, User flow는 다이어그램으로, 지표는 표로 쓴다. 자세한 깊이 기준은 `quality-principles.md`의 "깊이 기준", 완성된 예시는 `example-case-study.md`를 본다.

## 원페이저 요약 (본문 앞, 필수 — 단계 아님)

**목적**: 리크루터·심사위원은 첫 30초에 판단한다. 문서 최상단에 4줄 요약을 둔다.

**갭 분석 시 확인할 질문**
- 한 문장으로 이 프로젝트는 무엇인가요?
- 가장 내세울 임팩트(숫자 or 성과) 한 가지는?
- 이 프로젝트에서 본인의 역할/기여는 무엇이었나요? (혼자면 "어떤 판단을 직접 했는지")

**문서 섹션 템플릿**
```
## 요약 (One-pager)
- 문제:  (누구의 어떤 불편)
- 해결:  (무엇을 만들었나)
- 임팩트:  (핵심 숫자/성과 — 없으면 목표치)
- 내 역할:  (PM으로서 직접 내린 판단·한 일)
```

## 1. 기획 검증

**목적**: 문제 정의, 타겟 유저, 비즈니스 가설, 시장/경쟁 맥락이 명확한지 검증한다.

> **`참고 자료 (아이디어 소스)`는 필수 섹션이다.** 구상 단계 프로젝트든 완료 프로젝트든 예외 없이 채운다 — "무엇을 보고 이 생각에 도달했는지"는 심사관이 기획의 근거를 확인하는 지점이다. 링크만 나열하지 말고 **출처 → 얻은 것 → 기획에 반영한 방식**까지 쓴다. 사용자가 출처를 주지 않으면 지어내지 말고 `[추가 입력 필요]`로 남긴 뒤 최종본 전에 반드시 다시 요청한다.

**갭 분석 시 확인할 질문**
- 어떤 문제/불편함을 해결하는 서비스인가요?
- 주요 타겟 유저는 누구인가요? (연령, 상황, 니즈)
- 비슷한 서비스/경쟁자는 누구고, 우리의 차별점은 무엇인가요? 시장은 얼마나 큰가요(대략)?
- **(필수) 이 아이디어를 구상할 때 참고한 페이지·자료는 무엇인가요?** — 글·영상·커뮤니티 게시글·경쟁 서비스 페이지·논문 등. **URL(또는 출처명)을 아는 만큼** 알려주세요.
- 그 자료에서 각각 **무엇을 얻었고, 그게 기획 판단에 어떻게 반영**됐나요? (예: "가격 페이지를 보고 월 4,900원 선을 잡음")
- 핵심 기능은 무엇인가요? (2~3개로 압축) — 이 기능을 넣고 **뺀 기능**은 무엇이고 왜 뺐나요?
- 성공을 어떻게 측정할 건가요? (KPI 후보 — 가능하면 목표 수치까지)
- 대략적인 일정/마일스톤이 있나요?

**문서 섹션 템플릿**
```
## 1. 기획 검증
### 문제 정의
### 타겟 페르소나
### 경쟁/시장 맥락 & 차별점
### 참고 자료 (아이디어 소스)
### 핵심 기능 (PRD 요약)
### 의사결정: 무엇을 넣고 뺐나 (스코프 결정 근거)
### KPI 가설 (목표 수치)
### 로드맵
```

## 2. UX 설계

**목적**: 사용자가 실제로 서비스를 어떻게 이용하는지, 어디서 이탈·과금이 발생하는지 설계했는지 확인한다.

**갭 분석 시 확인할 질문**
- 회원가입부터 핵심 기능 사용까지 유저는 어떤 화면을 거치나요?
- 결제/과금이 있다면 어떤 시점에, 어떻게 발생하나요?
- AI 기능을 호출하는 시나리오는 무엇인가요? (예: 챗봇 질문, 추천 요청)
- 예외 상황(에러, 실패, 한도 초과 등)은 어떻게 처리하나요?
- 유저 행동을 어떤 이벤트로 추적하나요? (트레킹 설계)
- 설계 중 고민했던 대안(예: 가입 먼저 vs 체험 먼저)과 최종 선택 이유는?

**문서 섹션 템플릿**
```
## 2. UX 설계
### User Flow
### 결제/과금 로직
### AI 호출 시나리오 & 예외 처리
### 트레킹 설계 (이벤트 정의)
### 의사결정: 설계 대안 비교 & 선택 이유
```

## 3. QA 검증

**목적**: 실제로 동작하는 프로토타입/MVP인지, 상품화할 수 있는 수준인지 검증했는지 확인한다.

**갭 분석 시 확인할 질문**
- 어떤 시나리오로 QA를 진행했나요? (정상 케이스 + 예외 케이스)
- 발견된 주요 이슈와 해결 과정은?
- 어떤 노코드 툴 + AI API 조합으로 구현했나요? — 이 조합을 **왜** 골랐나요(대안 대비)?
- 라이브 서비스로 배포 가능한 상태인가요? (도메인, 인프라)

**문서 섹션 템플릿**
```
## 3. QA 검증
### QA 시나리오 & 결과
### 기술 스택 (노코드 툴 / AI API) & 선택 이유
### 상품화 승인 기준 충족 여부
```

## 4. 마케팅 런칭

**목적**: 실제 유저에게 노출하고 반응을 얻었는지 확인한다. (아직 안 했으면 "계획"으로 작성)

**갭 분석 시 확인할 질문**
- 초기 유저를 어디서, 어떻게 모았나요? (채널, 예산)
- 몇 명에게 노출했고, 그중 몇 명이 실제로 써봤나요? (노출 수, 방문 수, 전환 수 — 아는 만큼 숫자로)
- 대표적인 유저 반응을 **직접 인용구**로 남길 수 있나요? (정성 데이터의 핵심)
- 예상과 다르게 나온 부분이 있나요?

**문서 섹션 템플릿**
```
## 4. 마케팅 런칭
### PoC 마케팅 플랜
### 초기 반응 지표 (노출→방문→전환)
### 유저 반응 (인용구 중심 정성 데이터)
```

## 5. 성장 증명

**목적**: 데이터 기반으로 개선하고, 그 효과를 지표로 증명했는지 확인한다. (아직 안 했으면 "계획"으로 작성)

**갭 분석 시 확인할 질문**
- 초기 반응을 보고 어떤 개선(퀵윈)을 시도했나요? 그 개선은 어떤 **가설**에서 나왔나요?
- 개선 전/후 지표 변화가 있나요? (전환율, 재방문율, 객단가 등 — 절대수 + 비율)
- 시도했지만 **실패/무효했던 가설**도 있나요? (있으면 솔직하게 — 심사관이 높게 봄)
- 수익 모델(BM)은 구체적으로 어떻게 설계했나요? (무엇을, 누구에게, 얼마에 — 유닛이코노믹스: 1인당 원가 vs 과금)

**문서 섹션 템플릿**
```
## 5. 성장 증명
### 퀵윈 개선 내역 (가설 → 실험 → 결과)
### 개선 전후 지표 비교 (ROI)
### 실패했거나 배운 가설
### BM 구체화 (유닛이코노믹스)
```

## 6. 데모데이 크리틱

**목적**: 프로젝트의 최종 성과와 회고를 정리한다.

**갭 분석 시 확인할 질문**
- 최종적으로 상용화 도메인(URL)이 있나요? (없으면 계획 URL/도메인 후보)
- 가장 자랑할 만한 성과는 무엇인가요? (숫자로 표현 가능하면 숫자로)
- 아쉬웠던 점, 다음에 시도하고 싶은 것은?

**문서 섹션 템플릿**
```
## 6. 데모데이 크리틱
### 최종 성과 요약
### 론칭 URL
### 회고 (잘한 점 / 아쉬운 점 / Next Step)
```
